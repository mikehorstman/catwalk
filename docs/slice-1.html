Catwalk · Slice 1

Finish the day

Goal: the daily loop is complete on the phone. You can see past days, a streak, a real Cat screen, and you can change the goal or start over. No map, camera, account, or real step source.

What the code looks like now

  • evaluateDay is pure and tested. It awards a flat AppConstants.dailyGoalXp (50) once per day.
  • HomeController owns all reading and writing of daily_progress and last_evaluated. Nothing else can see history yet.
  • DailyProgress stores xpAwarded as a bool, not how much.
  • Today’s record freezes its stepGoal the first time it is written.
  • Cat, History, and Settings are placeholders.
  • LocalStore already has clear().

Decisions to lock first

  • XP by goal: proportional to 6,000, rounded to the nearest 5, clamped 20–250. 6,000 → 50 (so current behaviour and tests hold). 12,000 → 100. 1,000 → 20. One function, one tunable constant.
  • Changing the goal applies from tomorrow. Today’s record keeps the goal it started with. Otherwise lowering it after a walk would hand out XP.
  • Streak counts consecutive completed days. A day with no completed record before today breaks it. Today never breaks it, and adds one only when completed. No freezes yet.
  • Reset asks to confirm, clears the whole store, and returns to onboarding. Cat and history are gone.

Build order

1. Pull history out of the controller

  • New HistoryRepository (read all days, write today) under features/daily_goal/data/, using LocalStore. Move the JSON code from HomeController into it.
  • Provider for it. HomeController calls it.
  • No behaviour change. Existing tests stay green.

2. Goal-size XP

  • xpForGoal(int goal) in daily_goal/domain/. Replace the flat constant in evaluateDay with it, using the day’s frozen goal.
  • Add xpEarned (int, default 0) to DailyProgress next to xpAwarded. Old saved records without it still load.
  • Tests: 6,000 → 50, 12,000 → 100, clamps, still once per day, same-day re-evaluation does not pay again.

3. Streak

  • Pure currentStreak(history, today) in daily_goal/domain/. Add bestStreak if it costs nothing.
  • Tests: empty, gap breaks it, today incomplete does not break it, today complete adds one, missing day breaks it.

4. History screen

  • Replace the placeholder. Newest first: date, steps / goal, met or not, XP earned.
  • A streak line at the top. Empty state for a fresh install.
  • Reads through a provider on the repository, not the Home state.

5. Cat screen

  • Coat, name, level, XP to next level (from xpToReachLevel), mood, status, missed days.
  • Read-only. It shows state; it never decides it.

6. Settings: change goal

  • Slider or stepper 1,000–30,000 reusing the onboarding goal widget if it can be shared, otherwise extract it.
  • Writes the profile only. Text says “from tomorrow”. Home refreshes.

7. Settings: reset

  • Confirm dialog, then LocalStore.clear().
  • Invalidate the onboarding and home providers. The router redirect sends you to onboarding. Pop Settings first so no stale screen stays.
  • Test with the in-memory store: after reset, onboarding is not completed and history is empty.

8. Verify

  • flutter analyze clean, flutter test green.
  • On the simulator: complete a day with the debug buttons, see it in History, check the streak, change goal, reset, land on onboarding.

Out of scope

  • Real steps, the room, the map, extra cats, accounts.
  • Streak freezes (they come with map pickups).
  • Any change to how a runaway cat returns. It stays “any steps”.
  • Charts or weekly summaries.

Done when

A new user can play several days, read them back, see a streak, raise the goal and earn more per day, and wipe everything from Settings, with tests covering the XP, streak, and reset rules.
